# Lecture Slides

Respond in the user's language; slides are in the course's language.

## Two kinds of deck

| | Lecture deck | Research talk |
|---|---|---|
| Source | Module's slide outline (order, count) and content section | Final manuscript |
| Locked by | Slide count in the traceability matrix | Session length; numbers equal the manuscript |
| Tooling | A generator script + one style module, or hand-built from the outline | Any; a `.pptx` skill if available |

## Lecture decks

**Derivation.** Module → slide outline → deck. Slides never patch the module. If building a deck
reveals a module error, stop and report it (`rps-alignment`).

**When decks are generated by script** (recommended for a whole semester — consistent titles,
margins, and sizes across dozens of decks, and machine-checkable):

- **One style module** holds every colour, font, margin, and shape. Deck functions call its
  helpers (title, bullets, table, code, figure) and never set style values themselves.
- **System fonts only** (e.g. Segoe UI and Consolas on Windows labs). Other fonts are silently
  substituted on lab machines and break measured layouts.
- **A locked footer band** (course code, meeting, slide number); content stops above it.
- **Text that doesn't fit shrinks in steps to a floor**, then the *content* is shortened — never
  shrink further until it is unreadable from the back row.
- **Figures from the course figure pipeline**, rasterised to PNG when the slide library cannot
  take SVG; re-rasterise when the source changes. A figure not yet made shows as a labelled
  placeholder box so the deck is still usable.
- **A checker** verifies slide count against the matrix, nothing below the footer line, nothing
  off-canvas, and estimated text height within its box. It catches miscalculation, not small
  wrapping differences — **open the file and look**.
- The `.pptx` is an output: fix the generator, not the PowerPoint file.

## Design principles for teaching slides

From Mayer's multimedia learning research — the ones that matter most when a lecturer is
speaking:

| Principle | On a slide |
|---|---|
| **Coherence** | Remove decoration, decorative images, and text not needed for that slide's point |
| **Signaling** | Title states the key claim or question, not the topic; highlight the code line being discussed |
| **Redundancy** | The lecturer speaks, so no paragraphs to be read aloud. Keywords, code, figures |
| **Spatial contiguity** | Labels on the figure, not in a separate legend; explanation beside its code |
| **Segmenting** | One idea per slide; long code revealed in stages across slides |
| **Pre-training** | New terms introduced on their own slide before used in a larger explanation |

Practical limits: ≤ 6 bullets, ≤ 15 lines of code, one main figure per slide. Activity slides
say exactly what students do, for how long, and what they hand in.

## Research talks

- Numbers and figures come from the manuscript and its figure files — no number exists only on
  a slide.
- One message per slide; titles as claims, like Results subsection titles.
- About one slide per minute; backup slides after the closing slide for expected questions.
- Claims no stronger than in the manuscript (`academic-writing:research-integrity` if installed).

## When to stop and ask

- The module's slide outline and the matrix disagree on count.
- A deck needs a figure no module registers.
- Content will not fit even after shortening — the slide may need splitting, which changes the
  count (a matrix item).

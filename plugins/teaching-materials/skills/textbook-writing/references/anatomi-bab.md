# Chapter Anatomy

Numbers here come from the book outline. If the outline changes, this file follows — never the
reverse.

## One chapter

A stable sequence for every chapter (adapt to your outline, then keep it fixed):

| | Part | Source |
|---|---|---|
| 1 | Chapter learning outcomes | Module A (from the RPS indicators) |
| 2 | Concept map as a figure | Module B, redrawn as Figure N.0 |
| 3 | Content with applied examples | Module C, expanded into prose |
| 4 | "Common mistakes" box | Module D |
| 5 | Case study from a real organisational setting | Module C if present, else section K |
| 6 | Summary | Module F |
| 7 | Exercises and practical tasks | Module G, count per outline |
| 8 | Chapter references | Module I |

Front and back matter are built once, not per chapter: preface (including a statement on AI
tool use), how to use the book, chapter-to-CPMK map, table of contents; at the back, answers to
selected exercises, glossary, bibliography, index, about the author.

## Answer keys in the book

If the course reserves some exercises (e.g. even-numbered) for graded work, only the others are
answered in the book — printing the rest destroys their use. Keep one entry shape, for example:
`### Soal N ◆ <title>` → **Model answer** → **Must include** → **Common errors**. Programming
answers are one example solution, not the only correct one; say so in the back-matter
introduction. Grader-only notes are removed from the reader-facing version.

## Figure numbering

Chapter figure numbers **equal** the module's section J numbers. The concept map takes N.0
because no section J registers it. A missing figure is registered in the module, specified,
rendered, and only then used — never drawn ad hoc, which breaks visual consistency across
chapters.

## Known discrepancies

At readiness, compare three counts that often differ — the outline's estimated figure count,
the outline table's figure total, and the figures that actually exist — and **report** the
differences rather than choosing. Lists of "figures to draw" often mix figures with tables.

Page counts are estimates. If a written chapter far exceeds its range, report it; squeezing
prose into the range by cutting explanation is damage, not economy.

## Code in a chapter

- Every printed snippet is run; its output quoted as produced.
- The course's locked language version; no features from other versions.
- Naming follows the style the practicum rubric grades — the book must not model what is marked
  wrong.
- Deliberately defective teaching files stay defective; show a fix separately and explain the
  difference.

## Diagrams

If the course teaches a fixed symbol set (e.g. six flowchart symbols), no chapter introduces a
seventh, however fitting. A reader who meets an unknown symbol in chapter 9 concludes the list
in chapter 2 was incomplete.

## Temporary markers

```
[PERLU KEPUTUSAN PENULIS: studi kasus bab 6 memakai data koperasi atau puskesmas?]
[PERLU SITASI: klaim biaya rata-rata operasi sisip — sumber dan halaman]
[GAMBAR BELUM ADA: alur kerja pengujian, calon Gambar 13.4]
```

None remain when a chapter is declared finished. Record all of them in one place when the
chapter is handed to the author.
